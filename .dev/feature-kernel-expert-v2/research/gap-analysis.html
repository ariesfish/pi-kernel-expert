ForgeKernel 有什么，pi-kernel-expert 缺什么

结论先说：两者不是同一层的产品。ForgeKernel 拥有测量装置和路线图； pi-kernel-expert 拥有记录和知识检索。值得移植的只有约 6 条不变量和 1 套静态分析工具， 其余 90% 是为一台别人的 GPU 跑数小时无人值守循环而存在的基础设施，不该搬到 pi 里。

证据：两台本地仓库（A 10 579 行 TS / B 181 645 行 Python），5 个并行读者逐条带 file:line 落到 .dev/forgekernel-gap/notes/。无 GPU，未复跑任何实验；B 的数字均为其自报。

02真正致命的三处：现有结论可能是假的

① 你不知道那个数字量的是什么 —— 缺 host-bound 前置判据

benchmark_command 打一个数，contract 里没有任何字段能记下"这是 device 时间还是 e2e 时间"。 ForgeKernel 的实测事故：一个 pipeline 里的 "device" 读数中 46% 是 Python 派发，正确性全绿、可复现， 目标因此松了 1.86 倍，11.5 小时的 run 作废（timing_audit.py:1-33）。
noiseFloorPct 管的是方差，管不了有效性。

② 每个 speedup 都是跨 run 比值 —— 缺同 job 配对

现在比的是 .kernel/baseline.tsv（上一次 run 记的）与本轮中位数。ForgeKernel 量过这个偏差的代价： 第一个窗口快 3–5%，后续窗口热漂移 2.7% —— "超过 5% 等效区间的半壁"（timing.py:371-400）。 它的做法是 4 秒 burn-in + ref, kernel, kernel, ref 镜像，每侧取两次读数的均值， 并要求 ≥2 个比值、离散度 ≤5% 才允许下结论。

③ 一个 shape 只有一个输入 —— correctness 表面只有一半

contract 的 cell 只有 vars 和 boundary，无法表达"同一 shape 的第二组输入"。 真正难的内核（带 mask 的 attention、ragged 路由的 MoE、稀疏 indexer）错在数据分布上，不在 shape 上。 ForgeKernel 要求每个 shape ≥3 个 input group，各带 intent 和 seed，全部 shape × 全部 group 都判都测 （task.py:88, judge.py:186-201）。

第四处是顺序问题：scopeGlobs 只决定"什么算候选的改动"，并不阻止候选去改判它的比较器。 ADR 0004 自己写了这个暴露面："一个永远 exit 0 的比较器会产出全绿"。这条 guard 就是一个列表加一次 diff 检查。

04不该搬的部分

基础设施

  • GPU job 传输、ssh/tmux、GPU 锁、跨进程 resume、agent 会话管理。pi 是会话，不是守护进程；ADR 0001 已经把循环交给 pi-goal。
  • leaderboard 提交与打分。

为论文主张服务

  • 密封参考（sealref / closed_ref / fence 列表 / 密钥处理）：它要证明的是"agent 在看不到答案时能复现性能"，不是帮用户优化自己的 kernel。

45 条反作弊里的大部分

它们防的是一个对 benchmark 没有利益关系的 agent。可移植的是有效性子集（A1–A4），不是对抗性子集。单人 + 人类在环 + 优化自己真实的 kernel，风险画像不同。

700 行蒸馏策略

大量条目是"4 小时无人值守 + 弱模型"的失败模式补丁。搬 schema 和活下来的五条规则，不搬博物馆。

时间线 / PM / lever 定价的代码

重新推导它们的契约（判决行 + 覆盖地板 + 噪声地板），复制会连同 run 目录布局一起搬进来。

05反过来：这边已经更强的地方（别退回去）

  • contract hash + 生成脚本拒绝手改。ForgeKernel 没有制品级的这类拒绝，它的 guard 都是运行时检查。
  • 证据绑定 diff hash。ForgeKernel 把读数绑到 iteration + sha；"这份 profile 对这个树已过期"这条拒绝，是比它更干净的测量/记录分离。
  • pin 住、已净化、已做许可证审计的外部语料。hw_kb 只有第一方内容；没有第三方 pin、没有 fetch 时剪掉受限文件、没有注册时的冲突扫描。
  • 分发形态。一个包、一次安装，不要 venv，不要 GPU 侧预置。

06分阶段方案（每阶段以"新增一条拒绝"收尾）

P03–4 天
让读数有效 contract 增加 basis、referenceCommand?、harnessGlobs；读数记录增加 hostEnqueueMs / deviceMedianMs / hostBoundRatio / clocks。 kernel_candidate 拒绝：缺 basis 的 keep、hostBoundRatio ≥ 0.5 且无 host-free basis 的 keep、 diff 碰到 harnessGlobs 的候选。
验收：故意做厚 Python 的 bench 被点名拒绝；改 goal.checks.sh 的候选在买 GPU 之前就被拒。
P13–4 天
让数据面真实 cells[].groups[]（name / intent / seed），非 boundary cell 强制 ≥3 组；导出 KERNEL_GROUP； checks 跑全部 group；以校准后的参考误差做精度闸。
验收：在典型抽样上正确、在 zero_block 抽样上错的内核，矩阵判失败。
P25–6 天
让计划可寻址 kernel_milestone 校验 docs/milestone.md（章节、五元组、DAG、gate 块、[VERIFY:]/[MEASURED:]、gate 里不许 none）； candidate 必带 decision；拒绝进死路表（bundle 语义）；平台期由 kernel-diagnose skill 派一个 readonly subagent 产出 G/R 诊断 + patch 分类。
验收：没 decision id 的候选被拒；悬空 Depends on 的 milestone 被拒；平台期触发诊断记录而不是又一个候选。
P34–6 天
给 agent 仪器 把静态 SASS 六件套按 Apache-2.0 收进 third_party_licenses/（更新 NOTICE）做成 6 个 pi skill，每个一条判决行 + 一条 fail-closed 地板； 加 job-env-check；加 KB 容器（症状索引 + 五段 schema + lint + KB: 引用拒绝），先种 3–5 条在目标 arch 上复核过的条目，否则显式标 UNVERIFIED。
验收：Blackwell 内核的"ptxas 把我的 wgmma 打成了串行"由工具回答，不靠散文；无认证标记的 KB 引用被拒。
